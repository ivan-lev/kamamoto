# Статьи о керамике — общие правила

Правила для статей о японской (а также корейской и китайской) керамике на kamamoto.ru: о стилях и печах, гончарах, декоративных приёмах. Их используют четыре скилла, и каждый описывает только свой процесс:

| Скилл | Что делает |
| --- | --- |
| `ceramics-article-write` | пишет новую статью или новый раздел для готовой: ищет источники, ведёт журнал фактов, пишет текст и записывает его в локальную базу |
| `ceramics-article-review` | проверяет готовый текст и вносит точечные правки, которые выбрал пользователь: факты, транскрипция, термины, типографика, разметка |
| `ceramics-dictionary-links` | проходит по опубликованным статьям и ставит ссылки на словарь на первые упоминания терминов, которые появились в словаре после написания статьи; текст не меняет, только разметку |
| `ceramics-dictionary-terms` | добавляет термины в словарь `/dictionary` и правит существующие: формат записи (`id`, ромадзи, буква), определение, поиск дублей, запись в локальную базу |

Если правило касается текста статьи, оно записано здесь, а не в скилле. Меняя правило, правь этот файл.

## Где живут статьи

Статьи пишутся и правятся в dev-режиме, поэтому текст бери из локального API (`http://localhost:3000`), а не с kamamoto.ru: прод может отставать, а черновиков там нет совсем. Если локальный бэк не отвечает, попроси запустить `npm run dev` и только потом бери прод.

У всех разделов сайта статья устроена одинаково: поле `article` — массив блоков `{ content: HTML, slides: [{ filename, source, caption }] }`. После каждого блока на странице идёт слайдер с его фотографиями. Пользователь сам решает, где делить текст на блоки — например, чтобы поставить слайдер посреди раздела. Поэтому блок может начинаться с `<h2>`, с `<h3>` или вообще без заголовка, и это не ошибка. Отличаются коллекция, ключ и адреса:

| Тип | Коллекция | Ключ | Страница | Опубликованная | Черновик (`showArticle: false`) | Админка |
| --- | --- | --- | --- | --- | --- | --- |
| Стиль, печь, район | `styles` | `name` | `/ceramic-styles/<name>` | `GET /api/ceramic-styles/<name>` | в общем списке `GET /api/ceramic-styles/` | `/admin/ceramic-styles/` |
| Гончар | `potters` | `id` | `/lnt-potters/<id>` (только для ЖНС) | `GET /api/potters/<id>` | в общем списке `GET /api/potters/` | `/admin/potters/` |
| Декоративный приём | `features` | `name` | раздел ещё не подключён | — | только из Mongo: `db.features.findOne({ name: '<name>' })` | — |

- Черновик на запрос опубликованной статьи получает 404 с пустым телом, поэтому при 404 ищи запись в общем списке по ключу.
- Ссылку разбирай по адресу: `/ceramic-styles/<name>` → стиль, `/lnt-potters/<id>` → гончар; ключ — последняя часть адреса. По названию ищи в общих списках по `title` (у стиля) или `name` (у гончара).
- У гончара, кроме статьи, есть поля `name`, `japaneseName`, `lifeDates` и `info` (короткая биография, HTML). Имя, иероглифы и годы жизни в статье должны совпадать с ними; расхождение — ошибка, о которой нужно сказать пользователю. Сами поля правь, только если пользователь отдельно об этом попросил.
- Если раздел `features` уже подключили (отвечает `GET /api/features/`), бери статью из API так же, как у стиля.
- Образцы готовых статей: стиль — `GET /api/ceramic-styles/karatsu`, гончар — `GET /api/potters/kaneshige-toyo`.

Рабочие файлы скилла написания лежат в `temp/articles/<ключ>/` (папка `temp` в `.gitignore`):
- `article.html` — черновик для записи в базу: вся статья или новый раздел для готовой; блоки разделены строкой `<!-- block -->`. Сайт его не читает: источник правды — база, после записи черновик больше не нужен и перезаписывается следующим черновиком;
- `notes.md` — журнал фактов: утверждение, URL страницы, цитата оригинала. Если журнал есть, по нему видно, откуда взят каждый факт.

Если в базе статьи нет (запись ещё не создана), а `article.html` есть, текст для проверки и правки — этот файл.

## Транскрипция

Каждый язык — своя система. Смешивать системы в одном слове или имени нельзя.

### Японский — система Поливанова

| Слог | Запись | Пример |
| --- | --- | --- |
| shi, chi, tsu | си, ти, цу | Тикаси, Карацу |
| ji, zu | дзи, дзу | Хидзэн, Идзумияма |
| e (после согласной тоже) | э | Тэрасава, Кэндзё |
| sha/shu/sho, cha/chu/cho | ся/сю/сё, тя/тю/тё | Сёва, Тёсэн |
| ya/yu/yo (и в начале слова) | я/ю/ё | Ёкомакура, не Йокомакура |
| n перед b, p, m | м | Сампэй, тэммоку |
| n перед гласной или y | нъ | Синъити |
| долгие гласные | не обозначаются | Тохэн, Хоан, Сёмо |

- Озвончение в сложных словах (рэндаку) проверяй по словарю: 奥高麗 — Оку-Горай, 古唐津 — ко-гарацу. Для названий стилей принята форма «Мадара-Карацу»; чтение «-гарацу» фиксируй в словаре.
- Японские имена — фамилия первой: Накадзато Муан.
- Придворные титулы — строчными: Микава-но ками.

### Корейский — система Концевича

ㅊ → чх, ㅍ → пх, ㅌ → тх, ㅋ → кх; ㅂ/ㄷ/ㄱ/ㅈ в начале слова → п/т/к/ч; ㅓ → о, ㅗ → о, ㅡ → ы; фамилия 이 — «Ли» (одинаково на весь сайт). Примеры: пунчхон (분청), Чосон, Корё, Ли Сампхён.

### Китайский — система Палладия

zh → чж, ch → ч, sh → ш, x → с, q → ц, j → цз, z → цз, c → ц, r → ж; -n → нь, -ng → н; ye → е, -ui → -уй, -ian → -янь, -uo → -о. Примеры: Цзиндэчжэнь, Лунцюань, Цзяньяо.

### Смешанный контекст

- Корейские и китайские люди и вещи в японском контексте: выбери одну форму и держись её во всей статье — японское чтение по Поливанову (Ри Сампэй, тэммоку) или оригинальное по Концевичу/Палладию (Ли Сампхён, тяньму). При первом упоминании дай второе в скобках. Гибриды вроде «И Сампён» — ошибка.
- Китайские термины, ставшие японскими (天目, 青磁, 唐物), — по-японски, если речь о японской традиции; по-китайски, если о китайском изделии или печи.
- Корейский термин и японское название его разновидности различай: пунчхон (корейская керамика) ≠ мисима, кохики (японские названия разновидностей).
- Династии и эпохи — устоявшиеся русские формы: Тан, Сун, Юань, Мин, Цин; Корё, Чосон; Муромати, Адзути-Момояма, Эдо, Мэйдзи, Тайсё, Сёва. Даты — по таблице в разделе «Эпохи и династии».
- Ромадзи в русском тексте не используется.

## Термины и имена

### Термины

Первое упоминание термина в статье оформляется так:

| Случай | Как писать | Пример |
| --- | --- | --- |
| Есть русское слово, термина нет в словаре | русское слово (иероглифы, *чтение*) | `белый ангоб (化粧土, <i>кэсёдо</i>)` |
| Есть русское слово, термин есть в словаре | ссылка на словарь стоит на чтении | `белый ангоб (化粧土, <a href="/dictionary#keshodo"><i>кэсёдо</i></a>)` |
| Русского слова нет, термин есть в словаре | ссылка на транскрипции, иероглифы в скобках | `<a href="/dictionary#tataki"><i>татаки</i></a> (叩き)` |
| Русского слова нет, термина нет в словаре | транскрипция курсивом, иероглифы в скобках; термин — в таблицу «Словарь» | `<i>мидзубики</i> (水挽き)` |

- Термин в словаре — это термин из `GET http://localhost:3000/api/terms/`. В ссылке `<id>` — поле `id` термина (например, `waritake-shiki-noborigama`), а не сам термин. Сопоставляй по иероглифам (`kanji`) и названию (`title`), учитывая падежные формы.
- Дальше в статье — русская форма, а если её нет — транскрипция курсивом без ссылки. Ссылка на словарь ставится один раз на статью.
- Курсивом пишутся японские, корейские и китайские слова в русской транскрипции. Не курсивом: иероглифы, имена, топонимы, названия стилей, печей и эпох (Карацу, О-тяван-гама, Момояма).
- Один термин — одна форма во всей статье и в подписях к фото («кожетвёрдое состояние», «О-тяван-гама»).
- Названия стилей одинаковы в заголовке, тексте и подписи: «Кохики-Карацу».

### Люди

- При первом упоминании человека в статье — имя, иероглифы и годы жизни в скобках: «Накадзато Муан (中里無庵, 1895–1985)». Дальше — только имя.
- Если человек жив — «род. 1948»: «Атараси Кадзо (新佳三, род. 1948)». Если известна только одна дата — «?–1655». Если известен только век или период деятельности — «работал в 1630-х», «XVII век».
- Наследуемые имена с номером поколения — в одном формате на всю статью: «XIV Сакаида Какиэмон (十四代 酒井田柿右衛門, 1934–2013)».
- Корейские имена — хангыль и ханча, если они известны: «Ли Сампхён (이삼평, 李參平, ?–1655)»; китайские — иероглифы.
- Иероглифы и годы — только проверенные по источнику. Если годы найти не удалось, оставь иероглифы без годов и скажи пользователю, что годы не подтвердились. Если не нашлись и иероглифы, имя остаётся без скобок.
- В статье о гончаре это правило относится и к самому герою статьи: имя, иероглифы и годы — в первом предложении вступления. Сверяй их с полями `japaneseName` и `lifeDates`.

### Эпохи и династии

- При первом упоминании эпохи или династии в статье — её даты в скобках: «в эпоху Адзути-Момояма (1573–1603)», «при династии Мин (1368–1644)». Дальше — без дат.
- Если в той же фразе нужна дата события, она идёт в тексте, а не в скобках у эпохи: «в середине XIX века, в конце эпохи Эдо (1603–1868)». Не так: «Эдо (середина XIX века)».
- Границы ставятся по исторической периодизации: граница эпохи — это событие, которое её открывает или закрывает. Годы взяты из японских энциклопедий (kotobank: Nipponica, «Дайдзисэн», Heibonsha), а там, где словари расходятся, выбран вариант, при котором соседние эпохи стыкуются. Даты эпох, которые сейчас стоят в статьях сайта, скопированы из разных источников и образцом не служат: любое расхождение с таблицей — ошибка.
- Если источник статьи даёт другую границу (Камакура с 1192, Адзути-Момояма 1568–1600, Эдо до 1867 — так у большинства японских словарей, которые закрывают эпоху возвращением власти императору, 大政奉還), в тексте ставь табличную. Спорную границу обсуждай в тексте, только если она важна для сюжета (например, печь датируется самым рубежом эпох): тогда назови событие, а не только год.

## Факты и источники

- Каждый факт с датой, именем или числом подтверждай хотя бы одним японским первоисточником (п. 1–3 списка ниже). Английские и русские сайты — вспомогательные.
- Сайт антиквара или магазина не может быть единственным источником факта.
- Хронология: событие не может идти «после» того, что его исключает. Проверяй, не связаны ли даты в разных абзацах противоречием.
- Датировку начала производства бери по последним археологическим данным, а не по традиционной версии (часто «после походов Хидэёси 1592–1598», тогда как печи могли работать раньше).
- Династии и периоды сверяй: Корё (918–1392) ≠ Чосон (1392–1897). Границы периодов — по таблице в разделе «Эпохи и династии».
- Числа («около 70 печей») — только с источником; административную географию проверяй на текущую дату.
- Статусы — с годом и точным названием: традиционное ремесло (伝統的工芸品), исторический памятник (史跡), живое национальное сокровище (人間国宝), Japan Heritage.
- Спорные этимологии подавай как версии.
- Обобщения про группу проверяй («опала местных князей» может оказаться опалой одного клана).
- Непроверяемое убирай или помечай как требующее проверки.
- Источники пользователя (книги, сканы, PDF) — такие же источники, как сайты: факты из них проверяются, а о противоречиях с японскими первоисточниками нужно сказать пользователю.

### Где искать

В порядке надёжности:

1. **Официальные японские**: энциклопедии на kotobank.jp (Nipponica, Heibonsha, 美術人名辞典), Агентство по делам культуры (bunka.go.jp), «Культурное наследие онлайн» (online.bunka.go.jp, прежний адрес — bunka.nii.ac.jp), сайты префектур (`pref.*.jp`) и городов (`city.*.lg.jp`), их отделов образования и археологии, туристических ассоциаций, Ассоциация традиционных ремёсел (kougeihin.jp, densan-kaikan.jp), Японская ассоциация когэй (nihon-kogeikai.or.jp), некрологи и справки Токийского института культурных ценностей (tobunken.go.jp).
2. **Музеи и наука**: национальные, префектуральные и городские музеи, музеи керамики (ColBase — colbase.nich.go.jp), отчёты о раскопках печей, статьи на J-STAGE и CiNii, книги — через NDL Search (ndlsearch.ndl.go.jp).
3. **Сообщество ремесла**: кооперативы и союзы печей (協同組合, 窯元組合), официальные сайты печей и родов мастеров, фестивали керамики.
4. **Английские**: сайты музеев (Met, British Museum, V&A, MFA Boston, Freer), английские версии сайтов из п. 1–3. kogeijapan.com и kougeihin.jp — основные источники о процессе производства, см. «Процесс производства».
5. **Вспомогательные**: ja.wikipedia — не источник, а карта: смотри её сноски и иди по ним к первоисточникам. Сайты галерей и антикваров — только как дополнение к факту, подтверждённому выше.

### Как искать

- Ищи по иероглифам, а не по транскрипции: `唐津焼 歴史`, `中里無庵 陶芸家`, `site:kotobank.jp 金重陶陽`. Если иероглифов нет, сначала найди их (kotobank, ja.wikipedia, сайт печи).
- Шаблоны запросов: для стиля — `〇〇焼 歴史`, `〇〇焼 特徴 土 釉薬`, `〇〇焼 窯元 協同組合`, `〇〇焼 伝統的工芸品`, `〇〇焼 窯跡 発掘調査`, `site:kotobank.jp 〇〇焼`, `site:pref.〇〇.jp 〇〇焼`, `〇〇焼 製造工程`, `〇〇焼 作り方`, `〇〇焼 工程 土踏み`, `〇〇焼 人間国宝`, `重要無形文化財 〇〇焼 保持者`; для гончара — `<имя> 陶芸家 経歴`, `<имя> 人間国宝`, `<имя> 展覧会`, `<имя> 没`, `<имя> site:tobunken.go.jp`; для приёма — `<термин> 技法`, `<термин> 由来`, `<термин> 朝鮮`.
- Каждую найденную страницу открывай и на её /ja/ или /en/ версии: переводы часто расходятся с оригиналом.
- Запускай несколько поисков одновременно. Обычного поиска хватает для известных тем. Расширенный поиск сразу нужен для узких тем (малоизвестная печь, гончар без английских публикаций) и для свежих данных (число печей, статусы, смерть мастера), а также когда обычный поиск дал мало.
- Отчёты о раскопках (発掘調査報告書) часто лежат в PDF на сайтах префектур и в 全国遺跡報告総覧 (sitereports.nabunken.go.jp). Ссылайся на конкретный PDF и указывай страницу.
- Если страница не открывается (403, таймаут, сайт показывает текст только через JS), попробуй её версию на другом языке (/ja/, /en/), мобильную версию и копию в web.archive.org. Если не вышло — не считай факт подтверждённым этой страницей и назови её пользователю с пометкой «не открылась», чтобы он мог проверить сам или прислать текст.
- Если сайт найден только поиском, а сама страница не прочитана, на неё нельзя ссылаться как на источник факта.

### Процесс производства

Этапы производства стиля берутся из источников, где они описаны по шагам, а не восстанавливаются по общим знаниям о гончарстве. Искать — на двух сайтах о традиционных ремёслах, потом подтверждать независимым источником:

- **kogeijapan.com** — раздел «制作工程» на странице ремесла `https://kogeijapan.com/locale/ja_JP/<слаг>/`. Слаг — ромадзи без дефисов и долгот: `hagiyaki`, `karatsuyaki`, `kyoyakikiyomizuyaki`. Список керамики — `/locale/ja_JP/list/?category=4`. Читай японскую версию. Английская (`/locale/en_US/<слаг>/`) — только для сверки: из её перевода в статьи попали «процеживание», «утрамбовывание», «декорирование» вместо ангоба (таблица «Ошибки перевода с английского»).
- **kougeihin.jp** (Ассоциация традиционных ремёсел) — страница ремесла `https://kougeihin.jp/craft/<код>/`, список керамики — `/craft_industry/toujiki/` (Хаги — `0419`, Карацу — `0425`, Бидзэн — `0418`). Раздел «作業風景» — те же этапы, обычно с температурами и длительностью. Раздел «技術・技法・原材料» — официальные требования, по которым ремеслу присвоен статус традиционного: способы формовки, декора, глазурования, загрузки печи и какие глины допустимы. Это самый надёжный ответ на вопрос, какие приёмы традиционны для стиля.
- Этапы на этих двух сайтах совпадают, а текст пересказан, так что это одни и те же данные. Поэтому для подтверждения деталей они считаются одним источником. Второй источник должен быть независимым: сайт кооператива печей (〇〇焼協同組合), префектуры или города (страницы о традиционных ремёслах), музея керамики района, печи или мастера.
- Оба сайта охватывают только керамику со статусом традиционного ремесла (伝統的工芸品, 33 на 2026 год). Для стиля внутри района (Сино, Орибэ, Сэто-гуро → 美濃焼) процесс района — только общая рамка: то, что отличает сам стиль (глина, глазурь, обжиг), бери из источников о стиле. Для стилей вне списка (Раку, Охи) — сайты родов мастеров, печей и музеев.
- Этапы описывают район в целом. То, что делает одна мастерская, подавай с её названием, а не как правило для всех. Если числа расходятся (у kougeihin.jp обжиг Хаги в многокамерной печи длится 30–40 часов, а в очерке о конкретной мастерской на том же сайте — около суток), дай диапазон или обе версии и укажи, откуда каждая.
- Каждый этап записывай в журнал фактов, как любой другой факт: URL и японская цитата. Температуры и длительности — только из источника.

### Живые национальные сокровища

Если у стиля были или есть живые национальные сокровища, статья о стиле их называет — в разделе о мастерах. Официально звание называется «хранитель важного нематериального культурного достояния» (重要無形文化財保持者, так оно передано в статье о Канэсигэ Тоё), а «живое национальное сокровище» (人間国宝) — его общепринятое название. В статье пиши «живое национальное сокровище».

- Звание присваивают за технику, и её название не всегда совпадает с названием стиля. Канэсигэ Тоё признан по технике «備前焼», а Аракава Тоёдзо — по «志野» и «瀬戸黒», Хамада Сёдзи — по «民芸陶器», хотя работал в Масико. Поэтому одного запроса `〇〇焼 人間国宝` мало: ищи и по видам стиля (для Мино — Сино, Сэто-гуро, Кидзэто), и по спискам мастеров, связанных с районом, — их публикуют города и музеи района.
- Каждого мастера сверяй с официальной записью: «Культурное наследие онлайн» (online.bunka.go.jp), справки tobunken.go.jp, kotobank. Вторичные источники путают годы: у Канэсигэ Тоё встречаются и 1956, и 1959.
- В тексте — техника и год признания: «Аракава Тоёдзо (荒川豊蔵, 1894–1985) — в 1955 году признан живым национальным сокровищем по технике Сино и Сэто-гуро (志野・瀬戸黒)».
- Называй всех мастеров стиля за всю историю звания (оно существует с 1955 года), а не только ныне живущих. Со смертью звание снимается, поэтому об умерших — в прошедшем времени: «был признан в 1955 году». Если пишешь, сколько живых национальных сокровищ у стиля сейчас, укажи дату источника.
- Не путай звание с другими статусами и называй их своими именами:
  - признание коллектива-хранителя (保持団体認定): например, техника нигоридэ (濁手) и общество по сохранению технологии Какиэмона (柿右衛門製陶技術保存会, 1971) — это признание общества, а не человека;
  - хранители нематериального культурного достояния префектуры (県指定・県登録無形文化財): например, «陶芸 黄瀬戸・織部» в префектуре Айти (2023) — это звание префектуры, а не национальное.
- Если о мастере на сайте опубликована статья (`GET /api/potters/lnt`, «Ссылки внутри сайта»), при первом упоминании его имя — ссылка на неё. Подробная биография — в статье о мастере. В статье о стиле — имя, иероглифы, годы жизни, техника, год признания и одна-две фразы о его роли для стиля («Повторы»).

## Ошибки перевода с английского

Английские slip, glaze, shell, flask, tableware, turning — ложные друзья. Проверяй по японскому слову.

| Встречалось | Оригинал | Правильно |
| --- | --- | --- |
| белая глазурь | white slip / 化粧土 | белый ангоб |
| водная обточка | water turning / 水挽き | формовка с водой (мидзубики) |
| форма ракушки | shell / 砲弾形 | форма снаряда |
| утрамбовывают | 土踏み | топчут ногами |
| процеживание | straining / 水こし | отмучивание |
| обтёсывание | cutting / 削り | обточка, вырезание ножки (高台削り) |
| декорирование (как этап) | decoration / 化粧掛け | нанесение ангоба |
| разбивают серпом, измельчают молотом | 削り鎌で土削り, どんじいで凹凸をなくす | состругивают скребком, выравнивают молотом |
| столовые приборы | tableware / 食器 | посуда |

| железистая зола | iron glaze / 鉄釉 | железистая глазурь |

## Типографика

- Тире в предложении — «—» с пробелами; между годами и числами — «–» без пробелов (1592–1598); дефис только внутри слов.
- Кавычки «ёлочки», вложенные „лапки“; прямые и английские кавычки не использовать.
- Буква ё везде, где она есть (чёрный, путём, Четвёртая, Сёва).
- Градусы через пробел: 1300 °C.
- Никаких двойных точек, особенно после скобки с иероглифами.
- Века и поколения — римскими цифрами.
- Заголовки стилей по образцу: «Название-Карацу (漢字) — пояснение».

## Повторы

Одна мысль или факт излагается в статье один раз, в том разделе, к которому относится по смыслу. Повтор — это одно и то же содержание в двух местах, даже другими словами:
- один и тот же факт с подробностями (дата, имя, число, история) в разных разделах — например, в «Истории» и в «Мастерах»;
- абзацы или раздел, пересказывающие то, что уже сказано выше: вступление к разделу повторяет предыдущий раздел, вывод в конце раздела («Таким образом…») повторяет его же начало;
- описание одного вида, техники или печи в двух местах: в списке видов и ещё раз отдельным разделом;
- одинаковые по смыслу предложения внутри абзаца или соседних абзацев.

Повтором не считается:
- краткое упоминание во вступлении того, что подробно разобрано ниже: вступление называет, раздел объясняет;
- ссылка назад на уже введённое («упомянутый выше Ри Сампэй») без повторения подробностей;
- один факт в разных ролях: год основания печи в «Истории» и в краткой хронологии гончара, если хронология — отдельный итоговый список.

Если повторяющиеся места расходятся в деталях (разные годы, имена, числа), это уже фактическая ошибка, а не повтор.

Как устранять: оставить содержание там, где оно уместнее по смыслу, а в другом месте удалить или сократить до краткого упоминания, поправив соседние предложения, чтобы не остался шов. Существующие блоки при этом не объединяются и текст между ними не переносится («Локальная база»): если нужная формулировка стоит не в том месте, в нужном месте её пишут заменой, а лишнюю удаляют.

## Разметка

Текст статьи хранится в HTML редактора админки (tiptap: StarterKit с заголовками h2/h3, курсив тегом `<i>`, картинки с классом).

- **Пиши только эти теги:** `<p>`, `<h2>`, `<h3>`, `<ul>`/`<ol>` с `<li><p>…</p></li>`, `<blockquote>` (с `<p>` внутри — для цитат из источников: слов мастера, надписи, стихотворения), `<strong>`, `<i>`, `<a href>`.
- **Редактор сохранит, но в новый текст не добавляй:** `<u>`, `<s>`, `<br>`, `<hr>`. Если такие теги уже есть, оставь их. Исключение — когда они разбивают текст на куски вместо абзацев (серии `<br>`, `<hr>` между разделами): их стоит заменить на `<p>`.
- **Не трогай:** `<img src="..." class="...">` внутри текста — это картинки, которые пользователь поставил сам (классы вроде `article-image__left` нужны для вёрстки). Как и слайды, картинки не добавляются, не удаляются и не переставляются.
- **Редактор выбросит или изменит:** `<h1>`, `<h4>`–`<h6>`, `<em>` (станет `<i>` — пиши сразу `<i>`), `<span>`, `<div>`, `<table>`, `<code>`, классы на чём-либо, кроме `<img>`, атрибуты `style`, `target`, `rel` (`target` на сайте проставляется сам).
- **Переносы строк — как у редактора:** после каждого закрывающего блочного тега (`</p>`, `</h2>`, `</li>`, `</ul>`, `</blockquote>` …), после открывающих `<ul>`, `<ol>`, `<li>`, `<blockquote>` и после `<img>`.

Ошибки разметки:
- пустые `<p></p>`, абзацы из одного пробела, неразрывные пробелы `&nbsp;` подряд;
- метки `utm_*` в ссылках — убрать, оставить адрес страницы;
- ссылки на поисковую выдачу или главную страницу сайта вместо конкретной страницы (исключение — пункт списка источников, объединяющий несколько страниц одного домена, см. «Список источников статьи»);
- `<img>` не из `/static/` (с чужих серверов) — картинка может пропасть в любой момент.

## Ссылки внутри сайта

- На другие статьи ссылайся, только если они опубликованы. Списки опубликованных: стили — `GET http://localhost:3000/api/ceramic-styles/articles`, гончары — `GET http://localhost:3000/api/potters/lnt` (поле `link`). Общие `GET /api/ceramic-styles/` и `/api/potters/` для этого не годятся: они отдают и черновики.
- На словарь (`/dictionary#<id>`) ссылайся, только если термин уже есть в `GET http://localhost:3000/api/terms/`. Если нужного термина там нет, предложи его в таблицу «Словарь», а не ссылку. Как оформлять ссылку — в разделе «Термины».

## Список источников статьи

- Текст ссылки — доменное имя (kotobank.jp), ссылка — на конкретную страницу, а не на главную.
- Один домен — один пункт списка. Домен — хост адреса без `www.`; поддомены считаются разными доменами (`ja.wikipedia.org` ≠ `en.wikipedia.org`). Если с домена взято несколько страниц, ссылка ведёт на общий для них раздел сайта — ближайшую общую часть адреса, если по ней открывается настоящая страница раздела (оглавление, список статей, страница коллекции): `/bizen/history/kamakura.html` и `/bizen/history/edo.html` → `/bizen/history/`. Если такой страницы нет (адрес отдаёт 404 или перекидывает на главную) или общей части у адресов нет (`kotobank.jp/word/…` у всех статей kotobank — не раздел), — ссылка на сам домен: `https://kotobank.jp/`. Конкретные страницы при этом остаются в журнале фактов: по ним факты проверяются.
- Прежние источники статьи не удалять; добавленные — после них. Если новый источник с домена, который уже есть в списке, отдельный пункт не добавляется: ссылка существующего пункта меняется на общий раздел (или домен) по правилу выше.
- В список входят все сайты и книги, по которым написаны или проверены факты статьи.
- Книга — строкой «Автор. Название. Издательство, год», только если есть реальная библиографическая запись (например, в NDL Search).
- Список — последний блок статьи:

```html
<h3>Источники:</h3>
<ul>
<li>
<p><a href="https://kotobank.jp/word/...">kotobank.jp</a></p>
</li>
</ul>
```

- Заголовок — ровно `<h3>Источники:</h3>`, и список идёт сразу за ним. По этому заголовку сайт узнаёт список источников и выводит его сеткой в несколько колонок: классы tiptap не сохраняет, отличить список иначе нельзя. Сайт узнаёт и «Список источников», регистр и двоеточие не важны. Но с заголовком другого уровня или с другим текстом («Литература», «Ссылки») и если между заголовком и списком стоит абзац, список выводится обычным столбиком.

## Словарь

Если в статье встретились японские, корейские или китайские термины и имена, которых нет в `GET /api/terms/`, в конце ответа пользователю дай таблицу: запись в статье | иероглифы | чтение каной (для корейского — хангыль) | значение. Таблица нужна пользователю, чтобы решить, что добавить в словарь, поэтому поля базы (`id`, `letter`, ромадзи) в ней не нужны. Непроверенные чтения помечай звёздочкой.

Столбец «Значение» — готовое определение для страницы /dictionary, которое можно вставить без доработки, а не перевод в два-три слова. Как его писать — раздел «Определение» скилла [ceramics-dictionary-terms](../skills/ceramics-dictionary-terms/SKILL.md). Прежде чем вносить термин в таблицу, проверь, нет ли его в словаре в другом написании (紐作り = 紐づくり, `himo-zukuri` = `himozukuri`).

Добавляет термины из таблицы в базу скилл `ceramics-dictionary-terms` — после того как пользователь выбрал, какие добавлять. Под таблицей подскажи это одной строкой.

## Локальная база

- Писать только в локальную базу. На прод ничего не отправлять: не запускать `db:push`, `upload:*`, `ops.sh` и не делать изменяющих запросов к kamamoto.ru. Выкладывает правки на прод только сам пользователь.
- Менять только поле `article` в коллекции статьи (`styles`, `potters` или `features`, см. «Где живут статьи»). Остальные поля не трогать: у стиля — `name`, `title`, `showArticle`, `thumbnail`, `mapImage`, `description`; у гончара — `id`, `name`, `japaneseName`, `lifeDates`, `photo`, `info`, `isLNT`, `showArticle`. Публикация и SEO — решение пользователя. Поля гончара правятся, только если пользователь отдельно попросил, с тем же бэкапом, diff и проверкой на параллельную правку.
- Существующие блоки не объединять и не делить, текст между ними не переносить: как делить статью на блоки, решает пользователь. Новый раздел добавляется новыми блоками между существующими.
- Слайды не трогать: не добавлять, не удалять, не переставлять, не менять файлы и `source`. У новых блоков слайдов нет (`slides: []`), фото к ним подбирает пользователь. В подписях к существующим слайдам (`caption`) можно исправлять только явные ошибки: факты, транскрипцию, типографику, единообразие с текстом. Картинки `<img>` внутри текста — по разделу «Разметка».
- Перед каждой записью — бэкап локальной базы (из корня репозитория; значения из `.env` не читать и не выводить). `<действие>` — `edit`, `insert` или `write`:
  ```bash
  node_modules/.bin/dotenv -e .env -- bash -c 'mongodump --quiet --host "$DB_HOST" --port "$DB_PORT" --db "$DB_NAME" -u "$DB_USER" -p "$DB_PASS" --authenticationDatabase admin --archive --gzip' > "mongo/backups/local-pre-<ключ>-<действие>-$(date +%Y%m%d-%H%M%S).gz"
  ```
  Пароль в URI для `mongosh` не подставлять (в нём спецсимволы) — только флагами `--host/--port/-u/-p --authenticationDatabase admin`, как выше.

### Точечная правка

Так вносятся исправления в существующие блоки и новые пункты в список источников (`<coll>` — коллекция, `<keyField>` — `name` у стилей и приёмов, `id` у гончаров):

1. Выгрузить сырой документ из Mongo (`EJSON.stringify(db.<coll>.findOne({ <keyField>: '<ключ>' }))`), а не из API: API подменяет имена файлов слайдов на URL.
2. Вносить точечные замены «старый фрагмент → новый»; каждый старый фрагмент должен встречаться в блоке ровно один раз, иначе остановиться и разобраться.
3. Перед записью показать diff по предложениям.
4. Записать с проверкой, что статья не изменилась с момента выгрузки (пользователь может править её в админке параллельно): `db.<coll>.updateOne({ <keyField>: '<ключ>', article: oldArticle }, { $set: { article: newArticle } })`. Если `matchedCount: 0` — статью изменили, выгрузить заново и повторить замены.

### Новая статья и новые блоки

Целую статью в пустую запись и новые блоки в готовую статью записывает скрипт [write-article.js](../skills/ceramics-article-write/scripts/write-article.js) из файлов `temp/articles/<ключ>/` — порядок описан в скилле `ceramics-article-write`.
