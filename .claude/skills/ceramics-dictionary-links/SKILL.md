# Ссылки на словарь в статьях

Словарь `/dictionary` пополняется, а статьи, написанные раньше, о новых терминах не знают. Задача — пройти по опубликованным статьям и поставить ссылку на словарь на первое упоминание каждого термина, у которого её ещё нет. Текст статьи при этом не меняется — только разметка вокруг термина.

Правила оформления терминов — в [.claude/specs/articles.md](../../specs/articles.md), разделы «Термины», «Ссылки внутри сайта» и «Локальная база». **Прочитай их перед началом работы.**

## Что сказать при вызове

Ничего обязательного нет: по умолчанию проверяются все опубликованные статьи и весь словарь.

| Что можно сказать | Пример | По умолчанию |
| --- | --- | --- |
| Какие статьи | «только Карацу», `kaneshige-toyo`, ссылка на страницу | все опубликованные: стили, гончары, приёмы (когда раздел подключат) |
| Какие термины | «добавил в словарь кохики и татаки» | весь словарь |
| Что делать | «только отчёт» | отчёт, затем запись бесспорных правок после подтверждения |

## Как работать

### 1. Поиск

Скрипт [find-terms.js](scripts/find-terms.js) читает словарь и статьи из локального API (`http://localhost:3000`, база не нужна). Если бэк не отвечает — попроси запустить `npm run dev`. Запуск из корня репозитория:

```bash
node .claude/skills/ceramics-dictionary-links/scripts/find-terms.js
# одна статья и только новые термины:
ONLY=styles:karatsu,potters:kaneshige-toyo TERMS=kohiki,tataki node .claude/skills/ceramics-dictionary-links/scripts/find-terms.js
```

`ONLY` — `<коллекция>:<ключ>` (`styles`, `potters`, `features`; ключи — в «Где живут статьи»), так можно взять и черновик. `TERMS` — `id` терминов.

Скрипт пишет в `temp/dictionary-links/`:
- `report.md` — находки по статьям со сквозной нумерацией: термин, вид находки, номер блока (с 1), контекст (упоминание в `⟦…⟧`) и предлагаемая замена;
- `edits.json` — черновик правок `{ n, auto, kind, collection, key, termId, block, old, new }`, `block` — индекс с 0.

Как скрипт ищет: по иероглифам (`kanji`) и по названию (`title`) — с падежными окончаниями, с дефисом или пробелом внутри и без русских слов вроде «камень» в названии. Заголовки, текст внешних ссылок и список источников не считаются. Транскрипция короче 5 букв вне курсива не ищется (слишком много ложных совпадений) — такие термины находятся по иероглифам.

### 2. Разбор находок

| Вид | Что значит | Что делать |
| --- | --- | --- |
| `wrap` (`auto: true`) | первое упоминание — курсив, ссылки на термин в статье нет | вносить, если контекст подтверждает, что это тот же термин |
| `manual` | транскрипция без курсива, чтение рядом с иероглифами, термин внутри более длинного курсива, иероглифы без чтения | решить по контексту (ниже) |
| `move` + `unlink` | первое упоминание без ссылки, а ссылка стоит ниже | перенести: оба пункта вместе; спросить пользователя, если ниже стоит объяснение термина, а выше — проходное упоминание |
| `italic-outside` | `<i><a …>…</a></i>` | вносить: правильный порядок — `<a …><i>…</i></a>` |
| `link-no-italic` | ссылка на транскрипции без курсива | вносить, если в ссылке транскрипция; если русское слово («живое национальное сокровище», «восходящих печах») — не вносить, русские слова курсивом не пишутся |
| `duplicate` | вторая ссылка на тот же термин | снять: ссылка ставится один раз на статью |
| `wrong-link`, `broken` | ссылка ведёт на другой термин или на несуществующий `id` | сказать пользователю, `edit` нет |

Каждую находку проверь по контексту в `report.md`, а при сомнении — по тексту статьи:
- **Тот же ли это термин.** Топоним, имя, название печи или стиля — не термин, даже если пишется так же: «острова Амакуса» ≠ «камень Амакуса», «Идзумияма» как место ≠ «камень Идзумияма», «Ракуяки Тяван'я» — название мастерской. Такие находки отбрасывай.
- **Нет ли упоминания раньше.** Скрипт не знает русских соответствий терминов. Прочитай текст до найденного места: если термин уже назван раньше по-русски («восходящая печь» — `noborigama`, «живое национальное сокровище» — `ningen-kokuho`), первое упоминание — там. Если рядом с русским словом есть чтение — ссылка на чтение (правила «Термины»); если чтения нет — ссылка на русское слово, без курсива. Такую правку допиши в `edits.json` сам (следующий свободный `n`, `kind: "manual"`).
- **Транскрипция без курсива** — по правилам «Термины» японские слова в транскрипции пишутся курсивом, поэтому замена `слово` → `<a href="/dictionary#id"><i>слово</i></a>` верна, если это действительно термин. Заглавная буква в начале пункта списка («Гома (胡麻)», «Сангири (桟切り)») — тоже термин.
- **Термин внутри длинного курсива** («<i>камамото рокусэй</i>») — обычно это другое понятие, и ссылка на часть его была бы неверной. Отбрасывай, если словарный термин не совпадает с понятием целиком.
- **Иероглифы без чтения рядом** — ссылку ставить некуда, не добавляя текст. Не добавляй: отметь в отчёте для `ceramics-article-review`. Иероглифы у терминов в тексте по правилам «Термины» больше не пишутся (они остаются только у людей и у названия стиля), поэтому их наличие рядом с термином — тоже пункт для `ceramics-article-review`; сама ссылка ставится на транскрипцию.

Свои правки дописывай в `edits.json` в том же формате. `old` должен встречаться в блоке ровно один раз; `new` отличается от `old` только тегами — скрипт записи проверяет и то и другое. Ссылка оборачивает курсив снаружи: `<a href="/dictionary#<id>"><i>…</i></a>`, атрибутов, кроме `href`, нет. Ссылки на словарь в заголовках не ставь.

### 3. Отчёт и подтверждение

Покажи пользователю по каждой статье (номера — из `report.md`, чтобы можно было ответить «внеси 1, 3, 5–8»):
- **внесу** — бесспорные правки: таблица № | термин | фраза с выделенным термином;
- **нужно решение** — перенос ссылки, спорные случаи, с твоей рекомендацией;
- **отброшено** — коротко, почему (топоним, имя, часть другого понятия);
- **для `ceramics-article-review`** — то, что нельзя исправить без правки текста: иероглифы без чтения, иероглифы у терминов (их нужно убрать), чтение не по Поливанову («Имбэ-дэ» при словарном «Инбэ-тэ»), битые ссылки;
- **несостыковки в словаре** — из конца `report.md` (одинаковые иероглифы у разных терминов, невидимые символы): они мешают сопоставлению, исправить их может пользователь в админке.

Если пользователь сказал «только отчёт», на этом всё. Иначе спроси подтверждение одним вопросом: внести бесспорные правки и какие из спорных.

### 4. Запись в локальную базу

По разделу «Локальная база» articles.md: только локальная база, только поле `article`, слайды не трогаются. Скрипт [apply-links.js](scripts/apply-links.js) вносит пункты из `edits.json` (`ONLY_N` — выбранные номера) и пропускает статью целиком, если фрагмент не нашёлся ровно один раз или статью изменили параллельно. Значения `.env` не читать и не выводить. Сначала сухой прогон:

```bash
DRY_RUN=1 ONLY_N=3,4,13 EDITS_FILE="$PWD/temp/dictionary-links/edits.json" \
	node_modules/.bin/dotenv -e .env -- bash -c 'mongosh --quiet --host "$DB_HOST" --port "$DB_PORT" -u "$DB_USER" -p "$DB_PASS" --authenticationDatabase admin "$DB_NAME" --file .claude/skills/ceramics-dictionary-links/scripts/apply-links.js'
```

Если прогон чистый — бэкап по разделу «Локальная база» (`<ключ>` — `dictionary-links`, действие — `edit`) и тот же запуск без `DRY_RUN`. Если статья пропущена — перезапусти `find-terms.js` для неё (`ONLY=…`) и разбери находки заново.

После записи перезапусти `find-terms.js` для тех же статей: внесённые пункты должны исчезнуть из отчёта, остаться — только отброшенные и отложенные.

## Итог

- Сколько статей проверено, сколько ссылок поставлено, перенесено и снято — по статьям, имя бэкапа.
- Что отложено до решения пользователя и что передано в `ceramics-article-review`.
- Напомни, что правки только в локальной базе: на прод их выкладывает сам пользователь.
