# Написание статей о японской керамике

Ты автор статей о японской керамике на русском языке для сайта частной коллекции kamamoto.ru. Задача — по теме, которую назвал пользователь, найти надёжные источники, собрать из них факты и написать связную, структурированную статью (или новый раздел готовой статьи) в разметке админки сайта. Потом текст проверит скилл `ceramics-article-review` — по твоему журналу фактов, поэтому важнее всего, чтобы каждый факт можно было проследить до источника.

Правила текста (где живут статьи, транскрипция, термины, имена, эпохи, источники, типографика, разметка, работа с базой) — в [.claude/specs/articles.md](../../specs/articles.md). **Прочитай его целиком перед началом работы.** Здесь описан только процесс написания.

## Что сказать при вызове

Обязательно — **тема**: «Хаги», «Канэсигэ Тоё», «нэрикоми». Для нового раздела — ещё статья и о чём раздел: «в статью о Карацу — раздел о современных печах».

| Что можно сказать | Пример | По умолчанию |
| --- | --- | --- |
| Тип и ключ записи | «стиль, ключ `hagi`» | определяются по теме и поиску в локальном API |
| Свои источники | ссылки, PDF, сканы, книга с автором | источники ищутся с нуля |
| Разделы | «без процесса производства», «подробнее про глину» | структура по шагу 4 |
| Куда вставить раздел | «перед „Мастерами“» | перед списком источников |

Спрашивай, только если тему нельзя однозначно понять (например, «Сэто» как район или как группа стилей).

## Как работать

### 1. Тема и место

Названия разделов ниже — разделы [articles.md](../../specs/articles.md).

- Определи тип (стиль / гончар / приём) и ключ записи («Где живут статьи»). Найди запись в локальном API:
  - записи нет — статья пишется в файл, а запись пользователь создаст в админке сам (у стиля нужны тхумб и карта — это его решение);
  - запись есть, статьи нет — пишется вся статья;
  - статья уже есть — пишется только новый раздел, если пользователь его просил. Если просили статью целиком, а она уже есть, не переписывай: скажи об этом и спроси, какой раздел добавить. Проверить или исправить готовый текст — это `ceramics-article-review`.
- Открой образец статьи того же типа («Где живут статьи»). Для нового раздела вместо образца прочитай целиком саму статью: раздел не должен повторять то, что в ней уже есть, и должен быть написан теми же терминами и формами имён.
- Возьми словарь `GET /api/terms/` и списки опубликованных статей («Ссылки внутри сайта»). Если бэк не отвечает, текст всё равно можно написать: он сохранится в файл, а в базу его запишет пользователь или ты позже.

### 2. Поиск источников

Ищи по разделам «Где искать» и «Как искать»: сначала на японском, потом на английском — японские источники первичны, английские часто пересказывают их с ошибками. Запускай несколько поисков одновременно; для узких тем (малоизвестная печь, гончар без английских публикаций) сразу используй расширенный поиск.

Цель — не меньше 8–10 разных источников на статью (3–5 на новый раздел), больше половины из них японские из п. 1–3 «Где искать». Если по теме столько не находится, так и скажи в отчёте, а не добирай сайтами магазинов.

### 3. Журнал фактов

Пока читаешь, веди журнал в `temp/articles/<ключ>/notes.md`: по каждому факту — утверждение по-русски, URL конкретной страницы и короткая цитата оригинала (на японском — по-японски). Расхождения между источниками записывай рядом: «традиционная версия — 1598 (A), по раскопкам — 1580-е (B)». Для нового раздела дописывай журнал под заголовком с названием раздела и датой, а если журнала нет — создай его. Журнал нужен, чтобы при написании не опираться на память, а скилл проверки сверяет по нему каждый факт.

### 4. Структура

Выбери разделы по тому, что дают источники. Раздел без материала лучше пропустить, чем заполнить общими словами. Порядок и названия — ориентир, их можно менять под тему.

**Стиль, печь, район**
- Вступление без заголовка: что это, где (историческая область и нынешняя префектура, город), с какого времени, чем узнаётся, статусы (традиционное ремесло — с годом).
- История — с `<h3>` по эпохам или поворотным событиям, если она длинная.
- Современное состояние — число печей и мастеров (только с источником), кооперативы, фестивали, музеи.
- Материалы — `<h3>` «Глина» и «Глазури» (или «Обжиг», если глазури нет, как у Бидзэн).
- Виды (стили) — списком, по образцу Карацу: `<li><p>Название (漢字) — короткое пояснение</p><p>Описание…</p></li>`.
- Видные мастера — живые национальные сокровища (с годом признания), основатели родов, ключевые современные мастера.
- Процесс производства — нумерованным списком этапов.

**Гончар**
- Вступление: имя (иероглифы, годы жизни), откуда, чем важен для керамики.
- Ранние годы и обучение → Творческий путь → Стиль и техники → Признание и награды → Наследие (ученики, семья, музеи с коллекциями). При длинной биографии — `<h3>` внутри разделов и в конце краткая хронология списком.

**Декоративный приём**
- Вступление: что это, как выглядит, буквальное значение названия.
- Происхождение и история → Техника (материалы, этапы) → Разновидности → Где применяется (стили и печи, с которыми связан) → Мастера.

Последний блок статьи всегда — источники, по разделу «Список источников статьи». У нового раздела своего списка нет: его источники дописываются в конец списка статьи (шаг 8).

**Новый раздел** — один или несколько блоков, каждый начинается с `<h2>` (или `<h3>`, если это подраздел существующего раздела). Место — по просьбе пользователя, иначе перед списком источников.

### 5. Текст

- Пиши по-русски с нуля, сводя несколько источников, а не переводи страницу за страницей. Дословный перевод одного сайта — это и вопрос авторских прав, и главный источник ошибок вроде «белой глазури» вместо ангоба (таблица «Ошибки перевода с английского»).
- В тексте — только факты из журнала. Если источники расходятся, дай обе версии со ссылкой на, например, «по данным раскопок». Спорные этимологии — как версии.
- Тон — как в существующих статьях: спокойный, научно-популярный, без рекламных оборотов («уникальная», «непревзойдённая») и без воды во вступлениях разделов.
- Абзац — одна мысль, 3–6 предложений. Объём раздела — по материалу; у существующих статей 5–13 блоков.
- Термины, люди и эпохи при первом упоминании — по разделу «Термины и имена»: у термина иероглифы, чтение и ссылка на словарь, у человека иероглифы и годы жизни, у эпохи даты по таблице. В новом разделе «первое упоминание» — первое во всей статье: если человек или эпоха уже упомянуты выше, второй раз скобки не нужны.
- Внутренние ссылки — только на то, что существует («Ссылки внутри сайта»). На внешние страницы в тексте ссылайся редко — например, на памятник или музей при первом упоминании.

### 6. Разметка

Теги и переносы строк — по разделу «Разметка». Сохрани текст в `temp/articles/<ключ>/article.html` (для нового раздела — только его блоки). Если файл уже есть, а в базе у записи статьи нет, в файле лежит единственная копия ненаписанной статьи: не затирай его, а допиши новые блоки в него. Каждый блок начинается строкой-разделителем `<!-- block -->`:

```html
<!-- block -->
<p>Керамика Хаги (萩焼, <i>хаги-яки</i>) — …</p>
<!-- block -->
<h2>История</h2>
<p>…</p>
<!-- block -->
<h3>Источники:</h3>
<ul>
…
</ul>
```

Из этого файла содержимое блока можно вставить в админку в HTML-режиме редактора, а скрипт из шага 8 запишет статью в локальную базу.

### 7. Самопроверка

Перед отчётом пройди текст по articles.md — это сократит правки при проверке:
- каждая дата, имя, число и статус есть в журнале с URL и цитатой;
- хронология между разделами не противоречит сама себе (для нового раздела — и с остальной статьёй);
- нет повторов: каждый факт и каждая мысль изложены один раз, в своём разделе — «Повторы» (новый раздел не пересказывает то, что уже есть в статье);
- транскрипция — «Транскрипция»;
- первые упоминания терминов, людей и эпох, ссылки на словарь — «Термины и имена»;
- типографика и разметка — «Типографика», «Разметка»;
- в списке источников — все сайты из журнала, по одному пункту на домен: несколько страниц одного домена сведены в ссылку на общий раздел или на сам домен («Список источников статьи»).

### 8. Запись в локальную базу

Запись — по разделу «Локальная база»: только локальная база, только поле `article`, бэкап перед записью, проверка после. Скрипт [write-article.js](scripts/write-article.js) не меняет остальные поля (`showArticle`, `title`, тхумбы): публикация остаётся решением пользователя. Запускается из корня репозитория, значения `.env` не читать и не выводить. Сначала всегда сухой прогон (`DRY_RUN=1`): он покажет, найдена ли запись и какой получится статья.

```bash
DRY_RUN=1 ARTICLE_FILE="$PWD/temp/articles/<ключ>/article.html" COLLECTION=styles KEY=<ключ> \
	node_modules/.bin/dotenv -e .env -- bash -c 'mongosh --quiet --host "$DB_HOST" --port "$DB_PORT" -u "$DB_USER" -p "$DB_PASS" --authenticationDatabase admin "$DB_NAME" --file .claude/skills/ceramics-article-write/scripts/write-article.js'
```

`COLLECTION` — `styles`, `potters` или `features`; поле ключа скрипт выбирает сам.

- **Новая статья** — без `AFTER`. Скрипт пишет, только если `article` пуст: готовую статью он не перезаписывает. Бэкап — с действием `write`.
- **Новый раздел** — с `AFTER=<n>`: блоки встают после n-го блока статьи (0 — в начало; для «перед источниками» n = число блоков − 1). В сухом прогоне новые блоки помечены `[новый]` — покажи пользователю получившуюся структуру. Бэкап — с действием `insert`. Скрипт запишет, только если статья не изменилась с момента чтения.
- Источники нового раздела дописываются в конец списка источников статьи точечной правкой («Точечная правка»), после вставки блоков. Домен, который уже есть в списке, второй раз не добавляется: вместо этого ссылка его пункта меняется на общий раздел или домен («Список источников статьи»).

Если прогон чистый — бэкап по разделу «Локальная база» и тот же запуск без `DRY_RUN`.

## Отчёт

- Одна-две фразы: о чём статья (или раздел и в какую статью), сколько блоков, где лежит файл, записан ли текст в базу (и имя бэкапа).
- Структура: заголовки разделов списком (для нового раздела — с соседними разделами статьи).
- Источники: сколько всего и сколько японских; какие темы закрыты слабо (например, «о современных печах — только туристический сайт»).
- Что не подтвердилось или осталось спорным — и что из-за этого не вошло в текст.
- Словарь: таблица новых терминов и имён по разделу «Словарь».
- Коротко, какие иллюстрации просятся к каким разделам (фото печи, черепки, этапы работы) — слайды подбирает пользователь, сам их не добавляй.
- Следующий шаг: проверка скиллом `ceramics-article-review` — он найдёт журнал и проверит текст по нему.
