# Термины словаря

Словарь `/dictionary` — коллекция `terms` в базе: одна запись на понятие. Статьи ссылаются на термин по его `id` (`/dictionary#tataki`), поэтому `id` после создания не меняется, а дубль — это две записи, между которыми расходятся ссылки и поиск. Задача скилла — добавлять термины так, чтобы они встали в словарь как родные, и не плодить дублей.

Общие правила проекта — в [.claude/specs/articles.md](../../specs/articles.md): **прочитай разделы «Транскрипция», «Типографика», «Факты и источники» и «Локальная база»** — по ним пишутся название и определение и делается запись в базу. Здесь — формат записи словаря и процесс.

## Что сказать при вызове

Обязательно только одно — **какие термины**. Подходит любой вариант:
- список: «карацумоно, сэтомоно, ваби-саби»;
- таблица «Словарь» из отчёта `ceramics-article-review` или `ceramics-article-write` — «добавь термины из таблицы»;
- статья: «добавь в словарь новые термины из статьи karatsu» — тогда сначала найди в статье термины, которых нет в словаре.

| Что можно сказать | Пример | По умолчанию |
| --- | --- | --- |
| Что делать | «добавь», «подготовь», «поправь определение хакэмэ», «проверь словарь на дубли» | «добавь» — запись после чистого сухого прогона; «подготовь»/«предложи» — только таблица |
| Свои определения | готовый текст из таблицы проверки | определение пишется по источникам («Определение») |
| `id` и ромадзи | «id сформируй сам» | формируются по правилам ниже |
| Фото | — | не задаются: пользователь добавляет их сам в админке |

## Формат записи

Образец — существующие записи (`GET http://localhost:3000/api/terms/`), но не все: у старых есть ошибки (`kamazirushi`, `siori` по Кунрэй, прямые кавычки, дефис вместо тире) — они не образец.

| Поле | Правило | Пример |
| --- | --- | --- |
| `id` | Хэпбёрн строчными: し/ち/つ/じ/しゃ → shi/chi/tsu/ji/sha (не si/zi); долгие гласные не обозначаются (陶芸 → togei, 急須 → kyusu); ん → n и перед b/p/m (tonbonome, renbo, inbe-te); частица の опускается (蜻蛉の目 → tonbonome). Дефис там, где в названии дефис или пробел. Только `[a-z0-9-]`. **После создания не меняется**: на него ссылаются статьи | `goyo-gama`, `kake-hanaire` ← «Какэ ханаирэ» |
| `title` | транскрипция по Поливанову с заглавной (articles.md, «Транскрипция»). Может начинаться с русского слова, если без него непонятно, что это («камень Амакуса», «Глазурь исубай»). Варианты — через «или» | «Гоё-гама», «Иси-хадзэ или иси-баку» |
| `kanji` | основное написание; варианты через « или » | `呼継 или 呼び継ぎ` |
| `romaji` | варианты для поиска через пробел. Поиск на странице ищет вхождение строки в `title`, `kanji`, `romaji` и `definition`, поэтому нужны все написания, которыми термин могут искать: как `id`; без дефиса; с пробелом вместо дефиса; с долгой гласной через `ou`/`uu`, если она есть; оба чтения при озвончении | `goyo-gama goyogama`, `togei tougei`, `yakishime yakijime` |
| `letter` | первая буква **японского слова** в транскрипции, строчная — а не первая буква `title`, если `title` начинается с русского слова. Ё — отдельная буква | «камень Амакуса» → `а`; «Живое национальное сокровище» (人間国宝) → `н`; «Ёхэн» → `ё` |
| `image` | не задаётся (`''`): фото подбирает и добавляет пользователь | — |
| `definition` | раздел «Определение» | — |

## Определение

Готовый текст для страницы словаря, а не перевод в два-три слова:
- 2–4 предложения, начиная со строчной буквы: «дословно «официальная печь» — в период Эдо…», «железистая глазурь, в которой…».
- Что это такое, чем отличается (материал, техника, цвет, форма), к какому стилю, печи или эпохе относится; если есть — буквальный перевод («дословно «…»») и другие названия.
- В словарь идут только термины керамики и смежных искусств (articles.md, «Словарь»). Имена людей, топонимы, учреждения и мастерские, слова вне ремесла (тануки, хассо-энги, бытовые и общекультурные слова) не заводятся и не предлагаются; если такое слово есть в списке на добавление — скажи пользователю, что оно не для словаря, и не записывай.
- Только проверенные факты (articles.md, «Факты и источники»). Чтение каной сверяй по kotobank (デジタル大辞泉, 日本国語大辞典) или японскому сайту по теме: 砲弾形 читают и ほうだんけい, и ほうだんがた — выбирать нужно по источнику, а не на слух.
- Типографика — по articles.md: «ёлочки», тире «—», буква ё.
- Разметка: определение выводится как HTML. Японские слова в транскрипции — `<i>…</i>`. Термин, который уже есть в словаре (или добавляется тем же запуском), — ссылкой: `<a href="/dictionary#<id>"><i>хакэмэ</i></a>`, курсив внутри ссылки. Других тегов не нужно.
- Парные понятия ссылаются друг на друга: *карацумоно* ↔ *сэтомоно*, *хакэ* → *хакэмэ*.

## Как работать

1. **Список терминов.** Собери термины из просьбы, таблицы или статьи. Возьми словарь из `GET http://localhost:3000/api/terms/` (если бэк не отвечает — попроси запустить `npm run dev`).
2. **Нет ли уже такого термина.** Ищи глазами по иероглифам, чтению и названию — в том числе в других написаниях: окуригана (紐作り = 紐づくり), дефис и пробел (`himo-zukuri` = `himozukuri`), русское слово в названии («камень Амакуса»). Если термин есть — не заводи второй; предложи дополнить существующую запись (раздел «Правка»). Скрипт на шаге 5 ещё раз проверит дубли, но первый взгляд — твой.
3. **Проверка.** Для каждого нового термина найди иероглифы и чтение в источнике и подтверди факты определения. Что подтвердить не удалось, не записывай молча: скажи пользователю и пометь в таблице.
4. **Файл записи** `temp/dictionary-terms/terms.json` (папка `temp` в `.gitignore`):
   ```json
   [
     { "action": "insert", "term": { "id": "hake", "title": "Хакэ", "kanji": "刷毛", "romaji": "hake", "definition": "широкая плоская кисть…", "letter": "х" } },
     { "action": "update", "id": "hakeme", "set": { "definition": "новый текст" }, "expect": { "definition": "текущий текст из базы" } }
   ]
   ```
5. **Сухой прогон** скриптом [write-terms.js](scripts/write-terms.js) (из корня репозитория; значения `.env` не читать и не выводить):
   ```bash
   DRY_RUN=1 TERMS_FILE="$PWD/temp/dictionary-terms/terms.json" \
   	node_modules/.bin/dotenv -e .env -- bash -c 'mongosh --quiet --host "$DB_HOST" --port "$DB_PORT" -u "$DB_USER" -p "$DB_PASS" --authenticationDatabase admin "$DB_NAME" --file .claude/skills/ceramics-dictionary-terms/scripts/write-terms.js'
   ```
   `ERROR` останавливает запись целиком: занятый `id`, пустое поле, `image` в новой записи, ссылка на несуществующий термин, курсив снаружи ссылки, невидимые символы, устаревший `expect`. `WARN` не останавливает, но каждый нужно разобрать:
   - **возможный дубль** — сравни записи; если это то же понятие, не добавляй, а предложи правку существующей;
   - **буква не совпадает с названием** — верно, только если `title` начинается с русского слова;
   - **типографика** — исправь в файле.
6. **Подтверждение.** Если пользователь сказал «добавь» с готовым списком — записывай после чистого прогона. Если «подготовь», «предложи» или есть спорные случаи (дубль, непроверенное чтение) — покажи таблицу (`id` | название | иероглифы | ромадзи | буква | определение) и дождись ответа.
7. **Бэкап и запись.** Бэкап по articles.md, «Локальная база» (`<ключ>` — `dictionary`, действие — `insert` или `edit`), затем тот же запуск без `DRY_RUN`.
8. **Проверка.** Новые и изменённые термины отдаются в `GET /api/terms/`, страница `http://localhost:5173/dictionary` открывается.

## Правка существующих терминов

- Меняются только `title`, `kanji`, `romaji`, `definition`, `letter` — через `update` с `expect`: текущими значениями из базы. Если пользователь успел поправить термин в админке, скрипт его пропустит.
- `id` не меняется: на него ссылаются статьи. Если `id` неудачный, скажи пользователю; переименование — это новый термин плюс перенос ссылок в статьях, только по его просьбе.
- `image` не трогается: фото — решение пользователя.
- Термины не удаляются, даже дубли: на них могут ссылаться статьи. Найди ссылки (`node .claude/skills/ceramics-dictionary-links/scripts/find-terms.js` или поиск `dictionary#<id>` в статьях), покажи пользователю и предложи, какую запись оставить. Удаляет он сам или по его явной просьбе — после бэкапа.
- **Аудит всего словаря** — возможные дубли, битые ссылки, невидимые символы, типографика — тем же скриптом с `AUDIT=1` вместо `TERMS_FILE` (ничего не пишет). Находки покажи сводкой; правки — только выбранные пользователем.

## Итог

- Что добавлено и изменено: таблица `id` | название | буква; имя бэкапа.
- Что не подтверждено (чтение, факт) и что не добавлено из-за дубля.
- Предложи расставить ссылки на новые термины в статьях скиллом `ceramics-dictionary-links` (`TERMS=<id через запятую>`).
- Напомни, что запись только в локальной базе: на прод её выкладывает сам пользователь.
